# テーマから未知の情報源を発見する

ユーザーが渡すのは「何を知りたいか」。出典サイトと最初のURLは指定しなくてもよい。一般検索・論文検索から入口を作り、観測したリンクを別サイトへ辿り、取得本文で裏付けられる回答を返す。

## 入口と探索の進め方

1. テーマを検索語へ置き換える。和名・英名・正式名称・現場の専門用語を使い、情報が見つからなければ観測から検索語を追加する。
2. 一般検索で関連する組織・資料名・著者を発見する。学術テーマではCrossrefの書誌検索も使い、DOIや掲載先を候補にする。
3. 検索結果のリンク、参考文献、著者や組織のページを辿る。検索語を変える場合も新しい検索URLは実行器が作り、モデルが架空の出典URLを作ることはない。
4. 回答に必要な本文を取得する。検索結果と書誌情報は情報源発見の手がかりであり、論文本文を読んだ根拠として扱わない。
5. 回答文ごとに出典URLと原文引用を付ける。出典が主張を裏付けるかはLunaが判断し、引用が実際に提示・保存された本文と一致するかは実行器が検証する。

専門家の呼び方や隣接分野の用語を拾って再検索することと、出典の参照先を辿ることが、既知の検索語・サイトから抜け出す手がかりになる。現在の実装で追える参照先はHTMLリンクとCrossrefのURL。リンクのない文献名から自動でDOIを照合する処理は未実装。

## コマンド

```bash
python3 -B -m jse.lab topic \
  --run .lab-output/my-topic \
  --topic '調べたい情報と、必要な地域・時点' \
  --query '初期検索語' \
  --provider duckduckgo --provider crossref
python3 -B -m jse.lab run --run .lab-output/my-topic
```

`topic`は設定とrunを作るだけで、通信もモデル呼出しも始めない。初期検索語は最大3件。省略するとテーマをそのまま使う。providerはDuckDuckGo HTML・Mojeek・Crossref・Mwmbl・Wiby。既定はDuckDuckGoとCrossref。追加APIキー・有料検索サービスは不要だが、到達できることは保証しない。

無料HTML検索の確認ではMwmblとWibyの検索結果本文・リンクを取得できた。`--provider mwmbl --provider wiby`で選べる。Mwmblは`/search?q=...`へ直接送る。ルートURLからのリダイレクトでは、検索語に空白があるとLocationが不正になる例があった。両者の検索品質がGoogle相当とは確認していない。WibyのHTTPリンクは現在のHTTPS限定実行器では候補から落ちる。

[無料検索エンジンの実地確認](free-search-engines.md)に、検索結果取得と確認画面・拒否を区別した結果を記録した。

以後は[既存のLuna回答・計画判断・継続手順](cloud-lab.md)を使う。ユーザーがテーマと自由な探索を依頼済みなら、その許可の範囲で対象候補と小さな予算を具体化し、許可内容を判断noteへ記録する。ページごとの確認は不要。新しいサービス契約、目的変更、増額は別判断になる。

既定の全体上限は2arm合計で80 HTTP・16MBの保存本文・24成功ページ、エージェント要求10回。各armは40 HTTP・8MB・12成功ページ・24 URL試行・8 origin・検索語6件。robots、リダイレクト、検索、失敗にも同じ上限を適用する。失敗時の予約bytesは返却しない。設定を変える場合は取得前に設定を具体化し、新規runとして初期化する。

`public_web`は、探索中に見つかる公開HTTPSサイトを対象とする事前の範囲指定。取得originはHTTP台帳から数え、再開しても戻さない。認証情報付きURL、非HTTPS、標準外ポート、私設IPの直接取得は拒否する。DNSとproxyに関する既存の制約は引き続き適用される。Cloudのネットワーク許可とコマンド側のネットワーク権限も必要。`discovery`のない従来設定は、従来どおり指定originの外へ出ない。

## 出力と保存

テーマ探索のreviewには最後の取得ページを含むLuna armの全成功ページを渡す。ただし本文観測は各ページ先頭6000文字に限定し、切り詰めを表示する。

- `ANSWER.md`: 回答文、出典URL、原文引用、取得時刻、未解決の問い。
- `answer.json`: 回答文と引用の対応を機械可読で保存。
- `report.json`: 成功・失敗・取得予算・検索語・取得origin・引用照合。
- `state.json`、`requests`、`answers`、`blobs`: 再開と保存本文の再検証に必要な証跡。

```bash
python3 -B -m jse.lab verify --run .lab-output/my-topic
python3 -B -m jse.lab export --run .lab-output/my-topic \
  --output .lab-output/my-topic-checkpoint.zip
```

同じrunの結果判断待ちで、全ページ未取得・最後の失敗がProxyError/TimeoutErrorなら既存のretryを使える。`--all-seeds`を付けると、現在の最新試行が通信失敗となった設定済みseedをまとめて戻せる。HTTP拒否・robots拒否は再試行対象にしない。過去の失敗・予算・モデル回答を保持する。

## 評価と限界

目的を満たす出典付き回答ができたか、各主張をどの資料が裏付けるか、未解決の問いが何かを確認する。独立した情報源かは引用元と発信者を辿って判断し、複数URLをそのまま独立した裏付け数と数えない。現在の実行器は意味的正しさや情報源の独立性を自動認定しない。

Lunaは追加検索を行えるため、BFSとの比較は探索方法全体の比較。取得時刻・検索結果・検索語も異なり、リンク選択だけの効果や統計的優位は判定できない。網羅率は独立した正解集合がなければ未測定。検索に現れないページやリンクされない情報も残る。

現段階ではlive/impitのHTMLとCrossref検索JSONに対応する。PDF、全文API、sitemap、アーカイブ、ログイン、クリック、テーマ探索でのブラウザ描画は未対応。ページの後半にしかない根拠は6000文字の観測窓へ入らず、回答に使えない場合がある。未確認の内容は推測で補わず未解決として返す。

reviewの回答待ちで後半の本文を確認したい場合は、次を使う。保存本文の末尾6000文字を新しい要求として提示し、元の要求を保持する。通信を追加せず、既存のエージェント要求上限を1件消費する。引用の位置は保存本文の開始位置へ補正し、同じ検証に通す。先頭・末尾以外の部分は未観測の場合がある。

```bash
python3 -B -m jse.lab review-tail --run .lab-output/my-topic \
  --note '保存済み本文の後半にある根拠を確認する'
```

## 実地試験

2026年10月1日（UTC）、個別テーマの指定がなかったため「未知の情報源を発見する調査手法」を試験テーマにした。runは`.lab-output/topic-discovery-20261002`（名前は日本時間の日付）。最初に渡したのはテーマと2件の検索語で、対象資料のURLは指定していない。

Lunaは検索結果から[Texas Medical Center Libraryの引用検索ガイド](https://libguides.library.tmc.edu/dbsearching/SnowballMethod_CitationSearching)などを発見した。ガイド中の「TARCiS」を追加検索語にし、Crossrefで関連文献のDOIを取得した。論文本文は未取得なので、最終回答は取得できたガイド本文の根拠に限定した。

両arm合計49 HTTP、予算計上10,106,396 bytes、取得12資料（HTML 11・書誌JSON 1）。通信失敗の予約6,000,000 bytesも計上したまま同じrunを継続し、予算はリセットしていない。最終回答は2文・原文引用4件。保存本文・提示された観測との照合は通過したが、意味的正しさの独立評価と網羅率測定は行っていない。両armともURL試行上限で停止したため、未訪問候補が残る。

今回の検証は54件の`test_lab*.py`テスト、実runの`verify`、チェックポイントの書き出しと復元検証。回答はrun内の`ANSWER.md`、探索記録は同名のチェックポイントZIPに保存する。次の試験では具体的なテーマを指定し、本文観測窓の拡張と、候補先頭60件に埋もれた情報源の選択方法を検討する。
