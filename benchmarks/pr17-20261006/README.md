# Controlled browser evidence

See [the Japanese report](../../reports/2026-10/pr17-ci-controlled-comparison.md).

`run-02` is the definitive run. `run-01` is a retained pilot with a harness routing failure; do not pool them. Root JSON files are readable summaries. All cell-level evidence and source snapshots are inside the corresponding verified `*-checkpoint.zip`. Raw working directories remain locally and are ignored to avoid duplicating the ZIP contents in Git.

Reproduction uses the code commit in `run-02/conditions.json`, pinned Camoufox setup, the saved fourplay package lock, and the verified upstream 4play 1.10 XPI (SHA256 `70937b52eada128b3966d0628d4aad7369abb9ed4357c03ab4576235de410fcb`). Install the lock in `.deps/fourplay`, extract the XPI into `.deps/fourplay/ext`, and set both `BOT_DIAGNOSTICS_FOURPLAY_EXTENSION` and `BOT_DIAGNOSTICS_CAMOUFOX_FOURPLAY_EXTENSION` to that directory. Use `environment/Browser.Dockerfile`; builds require the existing proxy and readable CA secret (`mode=0444`). No new credentials are needed.

Run the container as the workspace user, bind this repository at the same path, use `--network none --shm-size=512m`, start Xvfb `:99 -screen 0 1280x720x24 -nolisten tcp -ac`, then run:

```sh
node experiments/bot-diagnostics/controlled-fourplay-comparison.mjs NEW_OUTPUT_DIRECTORY
```

The fixture chooses an ephemeral loopback port and generates one fingerprint per invocation, shared by all Camoufox arms and recorded for inspection. A new invocation is a new fingerprint; it does not automatically replay the saved fingerprint. The image used here was `sha256:fe1be5b83ee8c7ccb9a00c341ff665ad46815fd65d4218dfc790311143dec55e`. Its base digest and installed package versions are preserved in `environment/`. Rebuilding against a moving apt repository can change the Firefox package; compare versions before combining runs.

Follow-up: `phase-02` contains the uncontended paired timing run (4 profiles/arm,
3 pages/profile) and an existing HTTP bridge observation. `phase-01` is a pilot
with concurrent validation and is not used for performance conclusions.
`wait-fixture-02` verifies late JavaScript readiness; `wait-fixture` is the retained
charset-failure pilot. `wait-public-02` contains the fixed two-site public comparison;
`wait-public` is the proxy-routing failure pilot. Each has a separate checkpoint ZIP.
See [the follow-up report](../../reports/2026-10/pr18-phase-and-wait-followup.md).

For public reproduction, use `environment/Network.Dockerfile` to add certutil, retain
the existing HTTPS_PROXY/HTTP_PROXY, mount the existing proxy CA read-only and set
BOT_DIAGNOSTICS_CA to it. If Docker resolves the proxy hostname differently from the
host, map only that hostname to the existing host-resolved managed proxy address
with `--add-host`. Do not disable the proxy, TLS verification, or environment controls.
The public image measured here is `sha256:afef86d59a272843b0040cfee67c46bdfaaefdbd5ea099f823bd72ffce9d614d`.
`camoufox-phase-comparison.mjs` needs a writable temporary `/run` bind for the existing
bridge's ephemeral local token; it deletes that token and excludes profiles from exports.
`summary.json` for phase-02 is generated by `summarize-phase-comparison.py results.json`.

`bridge-gate` and `bridge-gate-ready` close the HTTP bridge blank-completion issue.
The latter is the final legacy/fixed/fixed/legacy run with opt-in selector readiness,
redirect, HTTP503 and never-completing resource cases. Run
`fourplay-bridge-gate-smoke.mjs NEW_DIRECTORY` in the same network-isolated container
with the writable ephemeral `/run` bind described above. It exits nonzero if the
fixed-arm readiness/status/deadline checks fail. Baseline source is pinned to
`ada0ff2615a3fcba132f2fde1bbd0a912d3fe897`; exact old/new server and helper sources are
also evidence blobs referenced by each cell's `bridge-sources.json`.
