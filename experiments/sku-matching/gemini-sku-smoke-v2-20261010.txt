Service-account Vertex setup
The user suggested service-account authentication for Vertex. For this six-case
smoke, call the Vertex model API directly; no Agent Engine deployment is needed.
Enable aiplatform.googleapis.com in groundingsearch and grant the calling service
account roles/aiplatform.user on that project. Configure its JSON credential as
the GCP_SERVICE_ACCOUNT_JSON environment secret, or use existing ADC.
The runner loads this JSON in memory, without writing credentials to output files.
Only the credential source category is recorded, not the identity or credential.
The --service-account-json-env flag can select a different secret variable name.
Model requests still use gemini-3.5-flash-lite with location global.
https://cloud.google.com/vertex-ai/generative-ai/docs/start/quickstart

The Vertex inputs have also been prepared without API calls. Offline credential
controls passed: valid service-account parsing and signing; malformed JSON,
invalid PEM, and wrong credential type rejected without secret disclosure; ADC
fallback when the secret variable is empty. No live credential was used.

OAuth alternative without a service account
In Cloud Shell signed in as the user's Google account, obtain a short-lived token:
gcloud auth print-access-token
Configure only the returned token as the GCP_ACCESS_TOKEN environment secret.
The runner uses it as a Bearer credential for Vertex, redacts its value from
artifacts, and cannot refresh it. Default token lifetime is about one hour.
For this token route, the quota-project header is set to the requested project.
Selection order is explicit token -> service-account JSON -> existing ADC.
For a local environment, user ADC can instead be configured with:
gcloud auth application-default login
gcloud auth application-default set-quota-project groundingsearch
The user's identity must have permission to invoke the Vertex model in the
groundingsearch project. No Agent Engine deployment or new account is needed.
https://docs.cloud.google.com/docs/authentication/rest
https://docs.cloud.google.com/docs/authentication/set-up-adc-local-dev-environment
Offline OAuth controls passed: Bearer header, secret redaction, multiline-token
rejection, and ADC fallback. No live token or model inference was used.
