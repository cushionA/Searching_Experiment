SKU 非LLM改善チェックポイント — 2026-10-10

概要
固定された楽天SKU 1件と、固定URLから取得したAU全商品行を比較し、二値の accept/drop を返すソース根拠型ゲートを記録した。未知・未確証は内部判定のまま自動dropし、人手確認フローは設けない。凍結入力、予測、変更差分、実装スナップショット、診断、実行ログをZIPに保存した。

最終ゲート結果
・旧実データ 1,383件（29商品）：baseline は accept 244 / drop 1,139。改善版は accept 426 / drop 957。
・再利用した機械ラベルとの照合は、人手未確認・独立goldではない。改善版は正解ラベル一致accept 426、誤accept 0、未一致drop 911、review扱いラベルdrop 37、見逃し9。照合上のprecision 100%、recall 97.9%。精度の独立推定や本番precisionとはみなせない。
・カーテンは333/333件をacceptし、非カーテンは93/102件をaccept、9件を見逃した。
・新規実データ56件はラベルを読まず、13件accept / 43件drop。ハンガー35件で5/30、マット6件で3/3、ワゴン6件で3/3、踏み台9件で2/7をacceptした。全行参照数は新規229、旧データ100,757。
・新旧合計1,439件の処理結果は accept 439 / drop 1,000。新規56件の受入れ数を旧データのラベル評価に加算していない。

モデル補助試行
・GLiNER 2.5 multi v1 のraw v2試行は97テキスト単位、68スパン。意味監査は支持62、誤り4、不明2。
・文脈拡張v4は169単位、139スパンで、支持123、誤り14、不明2。天板ラベルを捉えた一方、天板あり/なしをレース状態と誤分類する混同が残る。SKU最終採用には使っていない。
・日本語NLI v1（97ペア）はFP32で entailment 0 / contradiction 2 / unknown 95、動的INT8で unknown 97。v1両形式のargmax一致は24/97。短い主張に変えたFP32 v2は entailment 1 / contradiction 3 / unknown 93。config-check失敗はTransformers 5.17によるid2label JSONキーの型変換を設定不一致と誤認したもので、推論開始前に停止している。どのNLI試行もSKU精度ではなく、最終判定には未採用。
