## Kaggle Notebook / 実行履歴

- 初回Notebook v1はPapermillで `ValueError: No kernel name found in notebook and no override provided.` となった。nbformatの `MissingIDFieldWarning` も出ていた。これはkernel metadata不足とcell id warning。Notebook v2でkernel metadataを補い、実際のCUDA実行へ進めた。warning自体をkernelエラー原因と取り違えない。
- v2のGPU実行はTesla T4/CUDAで動作したがNotebook上限7200秒に達してcancelled。途中成果はraw score 34,345件/model（合計68,690件）とmodel出力として回収・検証済み。全971 ML pair完了ではない。ログにある旧prefix上限922と実測prefix1418が食い違うので、922を実績値として使わない。途中prefixを完了評価として扱わない。
- Kaggle監視時の `ConnectionError` はstatus取得/通信の失敗。GPU停止やjob失敗を示す証拠ではなく、ログprefixの再取得も停止証明にならない。通信が切れた場合は同じ固定refのstatus/wait/recoveryを続け、状態が確定する前に再submitしない。
- ローカルwait timeoutはローカル待機の期限切れであり、Kaggle jobの失敗や未提出を意味しない。同じjobをresume/waitしてからreceiptとterminal状態を照合する。新規submitで置き換えない。
- 古い83系jobはsubmission outcome unknown。明示的なref/versionと照合するまで再投入しない。曖昧なsubmitを再送しない。
- 初期28.5 MB payload転送もauto-reviewに拒否され、process未開始だった。その後ユーザーが非公開Datasetへの転送とGPU実行を明示許可し実行できたが、後続の120.7 MB worker-state/計算値入りpayloadは別物で、追加転送のauto-reviewに拒否された。拒否時点ではprocess開始・追加upload・submissionなし。ユーザーの「いいよ」と、適宜retryして最後までとの指示を得てから同じprivate Dataset v2へ追加転送し、resume-s000 v1を一度だけsubmit。Kaggle jobは正常完了し、新規15,616 records（7,808/model）を回収した。技術エラー0。ここは過去のapproval wait記述より後のreceiptが優先。現時点でその実験は完了済み。
- Kaggleのplanning previewは実行物ではない。`PREVIEW_BLOCKED` / do-not-submit previewをexecutable Notebook、upload、submissionの証拠として扱わない。
- GitHub pushは以前の外部転送auto-reviewでblockされたが、その後ユーザーが現行pushを明示許可した記録があるため、今はpending approvalとして扱わない。ただし、この記録だけから実push完了を主張しない。remote HEADを確認した事実が別途必要。
