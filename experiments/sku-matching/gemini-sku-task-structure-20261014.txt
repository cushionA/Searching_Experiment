# SKU choice validation task structure (preservation note, 2026-10-14)

Status: Luna accuracy validation is paused. This note preserves the existing public task format for a possible future Gemini validation. This document preserves a future-facing task structure; no Gemini run, model classification, inference, experiment, or accuracy claim is made here. Future work may begin with small models alone or a partial delegation; it need not recreate the full prior workload.

## Reusable task shape

Treat each assigned public packet as a self-contained, cold semantic task. It includes the protocol, pair identity, complete original option set, target/context facts, applicable scope, exact evidence and expected response shape. The worker should read the whole packet and its embedded instructions, assess every complete option independently, author every schema field, then submit one literal JSON object per pair in JSONL. First raw authored bytes are immutable. A malformed, missing, or unsupported judgment remains unknown for downstream accounting; do not repair or reclassify it in place.

The preserved semantic contract is the all-option / full-choice contract:

* Every original option is an independent complete vector. Assess the whole option, including all of its component values, rather than scoring fragments or only the chosen option.
* Keep the current selected target SKU, the captured target-SKU inventory, and the product/reference description as three distinct sources. A value observed for the selected SKU does not imply that other inventory values are excluded. Inventory membership does not establish which SKU is currently selected. Product-level description text applies across variants only when its quoted language positively establishes target-product scope and applicability.
* Establish same attribute, same subject, and applicable scope before a decisive support or explicit-conflict state. A mismatch is not a contradiction unless direct incompatibility/exclusivity is evidenced. No automatic exclusion of all other option values.
* Cite exact supplied selected-fact indices or exact normalized-body offsets/quotes as directed by the packet. Citation verification validates provenance and offsets; it does not prove semantic truth.
* Unknown is an allowed substantive outcome. Missing evidence, generic labels, uncertain scope, and unsupported applicability remain unknown; unknown is not contradiction.
* Preserve every original rowset and pair identity. Do not sample away, merge, or silently omit original rows. Freeze first-pass raw output before any grading or resolution.
* Grade only after output freeze, against the original machine labels and original rowsets. Keep first-pass outputs, validation receipts, case decisions, resolutions, and grades as separate artifacts. Do not use labels, prior model answers, private selection maps, or grades in a worker task.

## Code lineage and boundaries

Relevant code to inspect when designing a future runner is listed with hashes in the companion manifest: `sku_body_invariant_indexed_transport_v1.py`, `sku_body_invariant_choice_v3.py`, `sku_directional_choice_nli_v1.py`, `sku_directional_choice_nli_au_coordinate_v1.py`, `run_nextdata_table_experiment_v1.py`, and `prepare_body_indexed_volume_packets_v1.py`, plus `sku_body_invariant_choice_v3.schema.json`. These files define transport, extraction/validation, citation and schema boundaries; they are references, not a mandate to execute those scripts.

A future provider/model-neutral run must explicitly preserve the packet version, exact prompt/instructions, model/provider identifier and settings, per-task request/response bytes, failures/retries, ordering, and first-write hash. Keep provider-specific transport separate from task semantics. The former Kaggle NLI path is a different protocol and must not be presented as equivalent to these full-choice semantic judgments. Do not add category-specific rules or infer labels from the earlier Luna output. Establish a frozen small-model-only or clearly bounded partial-delegation scope before any future inference; compare only outputs collected under the same preserved task contract.
