Post-score diagnosis (label-free aggregate)

Indexed variant: 5 false negatives among 31 known references; 0 false positives. Literal-only variant: 11 false negatives. Six machine-labeled matched cases were accepted only by indexed matching. The score uses machine annotations, and unknown references are excluded from scored metrics.

For the five indexed false negatives, the gate returned drop/no_fully_supported_row in every case. There were 70 candidate rows across these cases and none reached a supported row state. The 232 task resolutions comprised 18 support, 130 conflict, and 84 unknown judgments. Source citation verification failed on 18 task resolutions across four cases; one case had verified citation links for all tasks. Every task had semantic_truth_verified=false, so citation linkage cannot establish the truth of the requested match.

The evidence supports three main failure modes: (1) unresolved model judgments over multiple condition axes despite citation linkage; (2) failed source citation verification on some required conditions, which leaves rows unresolved; and (3) candidate sets where conflicts or unknowns prevent any one row clearing every required condition. The data does not establish that the native inventory itself is incomplete: the observed issue is that no row passed the gate.

The six indexed-only accepts each had one unique row with support across all required conditions under the indexed-body invariant judgments; literal-only matching produced no fully supported row for those cases. These are prediction differences, not independent validation of semantic correctness.

Restricting the five false negatives to their score-referenced rows yields 16 required task resolutions: 7 support, 3 conflict, and 6 unknown. The authorized source bindings join every task to its pair reference. One unknown task used missing raw response ref 568 (packet refs mismatched); one used invalid response ref 220 (schema rejected an empty string), although its raw selected-option judgment said explicit conflict. The other four unknowns were raw model unknown judgments with pair-level source citations verified. The other four missing-response refs and six invalid-unknown refs do not join to these five reference rows.

All three reference-row conflicts came from selected_fact route judgments marked explicit_conflict. One rationale simultaneously said the option and target specify the same value, yet emitted conflict. Another treated a near-spelling color difference as a conflict; the third treated distinct complete selector values as exclusive. These are model judgments, and the contradictory size rationale is direct evidence of an inconsistency in the recorded output.

Across the six uniquely supported rows there were 27 supporting tasks: 18 selected_fact routes, one body_invariant route, and eight strict literal-family supports that had no model route. There were no selected_sku_body routes. This is a descriptive breakdown of evidence on accepted rows, not a causal decomposition of which route changed each case from literal drop to indexed accept; most supporting work came from selected facts and literal proofs, with one body-invariant task.

Future DEV-only work: improve source capture and citation binding for native variant/option fields; make condition-specific evidence and missing-source states explicit; and evaluate calibrated handling of broad inventories and semantically equivalent whole-value formulations. Test data must remain consumed and frozen; any development must use DEV data and be evaluated on a future untouched test set. No per-product or category exception is supported by this audit.
