What current CPU residual code already does

`trial_cpu_residual_axis_v2.py` (SHA256 `27c86cfc7c8632464d5d8bb6600f3a4c82489c5f805ec7874723833d1903c1a1`) builds per-condition title prompts and conditional description fallbacks. Its `common_axis_plan` compares common axes per AU row and distinguishes proven typed conflicts from unknown spelling differences. But `decide_case` returns case-wide review if any row has a common-axis unknown or AU-only axis; an unrelated row's unknown can therefore block a uniquely supported row. Prompt deduplication includes product, residual axis/value and common context; it sends a whole-product title and selected description blocks to the model, not arbitrary pools of SKU rows.

`trial_cpu_residual_axis_v3.py` (SHA256 `ee52b2d8cd2c6094fe3cb6b1e1e2ef0ae4948dda4eb34730ca68877d25964735`) recomputes the constrained-pair and canonical source gates over the full pool, checks a selected row's common axes, and keeps the model relation separate from direct source-fact and exact curtain-count resolutions. It is an ablation/evaluator, not a replacement baseline. The v10 constrained-pair source gate remains the decision baseline: its 337 known matches should stay in place until a new model task adds independently verified correct row accepts without damaging those matches.

Recommended staged task

1. Prepare a frozen, label-free host record per case. Retain all AU rows and their full `row_key`, original axis names and values, source refs, evidence, and candidate scope on the host. Preserve each Rakuten selected axis as `{axis_name_raw, value_raw, semantic_key_if_proven, normalized_value_if_proven, source_ref}`. Keep compound values opaque unless source-backed parsing can decompose every component; never rename an entire composite `カラー選択` value to `color` merely because one substring is a color.

2. Deterministically align common axes on the same AU row. Exclude a row only for a confirmed typed conflict or an unambiguous, provenance-backed crosswalk conflict. Exact matches and established crosswalks count as resolved; unknown aliases or arbitrary different strings remain unknown. A row with a missing common value is unresolved, not a Rakuten-only residual. Compare size/color conditions together on one row. An unrelated candidate row's unknown does not defeat a uniquely supported row, but two equally supported AU rows remain review.

3. Retain every selected condition from either side. After common axes are aligned, create one requirement per remaining selected condition: Rakuten-only conditions must be checked against the fixed AU title and scoped current-page evidence; AU-only selected conditions must also be reconciled or leave the case in review. Do not drop compound components, quantities, or unknown axes. A confirmed common-axis conflict cannot be rescued by a title phrase. Do not route to another AU URL.

4. Apply deterministic scope guards before any model call. The title is primary. Description fallback is eligible only when title evidence is unknown and the exact selected context applies. Carry all recognized conjunctions (such as width and color) into scope filtering. Exclude series/navigation/sibling links by their source DOM scope and `href`, not just by matching words. If source scope, condition, or product applicability is ambiguous, retain review. Exact typed proofs such as curtain panel-count conservation may resolve a condition before the model; require original row/source refs and complete same-scope accounting. A missing word alone never proves a negative.

5. Send one small semantic decision per residual requirement, not all AU SKU rows and not a whole two-product matching question. The prompt must say `商品候補ペアは決定済みだがSKU一致保証ではない`: product-pair resolution does not establish SKU equivalence. The model must check every Rakuten selected axis and every mandatory AU-only/page condition; a shared color or title keyword cannot stand in for omitted type, size, quantity, or set composition. Minimal model payload:

```json
{
  "condition": {"axis_name": "レースカーテン", "selected_value": "あり"},
  "matched_context": {"size": "100×90cm", "color": "ライトグレー"},
  "evidence": [
    {"source": "fixed_title", "text": "..."},
    {"source": "page_section", "scope": {"heading": "内容", "width_cm": 100}, "text": "..."}
  ]
}
```

   The model output is only `{"relation":"entailed|contradicted|unknown","evidence_indices":[0]}`. The runner binds results to frozen task order and selected row; the model does not emit case IDs, row keys, AU aliases, or arbitrary citation IDs. Evidence indices are small integers into that exact input array; validate range, type, and nonempty citations for a claimed entailment/contradiction. Invalid JSON, invalid indices, contradictory evidence, or low-confidence output becomes review. This directly removes the alias/citation-ID failure mode while keeping row selection deterministic and auditable.

Concrete source examples

• Curtain composition, AU product `704502086`: the full array has 153 cells in `au_sku_cells_raw`; an original row's `source_record_raw.column_option_value` is `幅100×丈90cm(4枚組)`. `au_product_options_raw.free_options[].title` includes `※幅100cmは4枚セット、幅150cmは2枚セットになります`. The fixed title is `$.itemInfo.itemTitle` and says `カーテン4枚セット` and `レースカーテンセット`. The AU original page `$.itemInfo.extraItemComment` has a single `内容` section with `【幅100cm】遮光カーテン 2枚 / レースカーテン 2枚` and `【幅150cm】遮光カーテン 1枚 / レースカーテン 1枚`. Thus width-100 total 4 equals drape 2 + lace 2; width-150 total 2 equals 1 + 1. The task must attach the right width scope to the selected row. For the 150-width example, another width's quantities cannot support the selected row.

• Curtain composition, AU product `704500131`: the same original fields give selected SKU values like `幅100×丈220cm(2枚)` or `幅150×丈178cm(1枚)`. The exact AU `$.itemInfo.extraItemComment` `内容` section is width-scoped: width 100 lists `遮光カーテン 2枚`, tassels, and hooks; width 150 lists `遮光カーテン 1枚`, tassels, and hooks. The 100-wide selected total is two drapes and zero lace; the 150-wide total is one drape and zero lace. This can support `レースカーテン=なし` by complete, same-width contents accounting, not by absence of the word “lace”. It contradicts a selected `あり` condition. The v8 evidence registry alone does not carry enough DOM/link structure for this proof; use original SKU `source_record_raw` plus original page JSON leaf and verify complete contents scope.

• Pet fence composition, AU product `653618158`: the fixed title leaf `$.itemInfo.itemTitle` is `50×50cm 13枚セット`. AU SKU cells contain only `カラー=半透明` or `カラー=透明`; they do not select 70×50 or 8/13/21-piece composition. In original `$.itemInfo.extraItemComment`, the heading says `こちらのページは50×50cm:13枚setです`; the following `▼ラインナップはこちら▼` contains anchors to `/item/756663950` (`70×50cm:8枚set`), `/item/756669532` (`50×50cm:8枚set`), `/item/729066856` (`70×50cm:12枚set`), and the current `/item/653618158` (`50×50cm:13枚set`). The v8 registry records these as description snippets but does not expose each anchor's `href` in the evidence item. Do not count the linked sibling offers as the current fixed page's selection. Rakuten's selected examples are 21 panels (20 panels + door), 13 (12 + door), and 8 (panels only), with 70×50 size; its own description says 21 = 13 + 8. Those Rakuten-side composition facts define the request, not evidence that AU sells that configuration. On fixed AU page 653618158 the 70×50/8 text is a link to another URL, so it cannot satisfy the current-page condition. Keep the 13/21/8 cases unresolved or explicitly conflicting based only on the current fixed page and same-row options; never follow sibling URLs.

• Compound shelf options, product `524251610`: v8 cases `case-0722ef51b816b9837580`, `case-590326f9f840ed0ef9b4`, and `case-da88a18f3fd0a6ebcfc6` carry Rakuten values `カラー選択=スリム / グレー`, `カラー選択=天板付き / 天然木`, and `カラー選択=本棚付き / 天然木`. The single AU row is `カラー選択=グレー`; fixed title `$.itemInfo.itemTitle` is a generic gray toy rack. Description snippets include `天然木おもちゃラック`, `1. BOOK RACK（本棚付き）`, `2. PLATE RACK（天板付き）`, and `3. スリムタイプ` in series sections. A shared `グレー` substring does not align the complete selected option. “Natural wood” at product level does not identify the selected shelf type, and sibling series descriptions do not prove which type the AU row selects. Preserve every component; exact common-axis conflict/unknown blocks title rescue, and type applicability stays review.

• Blanket set, `case-29c33146198b70eccc10`: Rakuten selection is `Key0=セミダブル / カラー選択=アッシュグレー / Key1=毛布セット`. The AU row selects only `カラー=アッシュグレー`; its title calls the product a mattress pad and general copy includes blanket-related words. A blanket reference is not proof the selected AU SKU includes a blanket set. Keep `毛布セット` as a required conjunction and review unless current-page evidence scopes the set to that exact selected row.

• Fence configurations, product `653618158`: the source cases include three distinct Rakuten compositions for the same fixed AU page: 21 pieces (`パネル20枚＋ドア1枚`), 13 pieces (`パネル12枚＋ドア1枚`), and 8 panels. The AU selection row `au:653618158:319149609:0:0` contains only `カラー=半透明`; it cannot establish any of those quantities or the Rakuten `70×50cm` size. The fixed title `$.itemInfo.itemTitle` says `50×50cm 13枚セット`; the current-page notice in `$.itemInfo.extraItemComment` says `こちらのページは50×50cm:13枚setです`. The same description's `▼ラインナップはこちら▼` lists 70×50:8 and other compositions as anchor links. Because the v8 `ad####` evidence snippets omit the anchor `href`, the task source packet must retain each original block's DOM scope and `href`; linked offers are not current-page proof. Thus quantity and size are mandatory even when color aligns, and page-level 13-piece evidence cannot satisfy the 21- or 8-piece request.

• Compound shelf selections, product `524251610`: the fixed AU row `au:524251610:334255147:0:0` supplies only `カラー選択=グレー`. The Rakuten cases request `スリム / グレー` (`case-0722ef51b816b9837580`), `天板付き / 天然木` (`case-590326f9f840ed0ef9b4`), or `本棚付き / 天然木` (`case-da88a18f3fd0a6ebcfc6`). AU title `$.itemInfo.itemTitle` describes a gray four-tier toy rack. AU description `$.itemInfo.extraItemComment` includes generic excerpts such as `回転本棚` and `天然木おもちゃラック`; Rakuten description refs include `rd0005` (`1. BOOK RACK（本棚付き）`), `rd0008` (`2. PLATE RACK（天板付き）`), and `rd0011` (`3.スリムタイプ`). The task must preserve each compound component and distinguish a current selected configuration from a product-family listing. Gray or natural-wood text alone leaves the requested type unresolved.

• Mattress selections, product `337595272`: Rakuten `case-2afdc5baa77e50f45d9d` selects `フラットタイプ / ダブル / アッシュピンク`; the aligned AU color option is `アッシュピンク（パイル）`. `case-2be8a29d7661fefb434f` selects `プロファイルタイプ / セミシングル / グレー`; the AU color option is `グレー（パイル）`. The AU fixed title `$.itemInfo.itemTitle` says `シングル`, and `$.itemInfo.extraItemComment` begins `こちらのページはシングルサイズです`. Other type/color words occur in page listing material, but they do not make the selected AU row double or semi-single, nor prove profile type. The required size and type conditions must be checked alongside color; a matching color suffix cannot rescue a fixed-size conflict.

• Across these examples, the model task should expose omitted conditions explicitly, rather than ask whether two whole products are “the same”: `{axis_name_raw, selected_value_raw, condition_scope, source_ref}` for every Rakuten axis and every AU-only mandatory condition. Output one relation per condition plus integer evidence slots. If a component has no current-page source, scope is unclear, a link points elsewhere, or evidence supports only a related product-family option, return `unknown`; do not collapse the condition into the matched color or infer an SKU from a shared family description.

Practical next test

Use the same 14 frozen real cases from the v8 upload, in a new run only after task schema and serializer hashes are frozen. This is a diagnostic, not a holdout. Keep all 153 curtain rows host-side; deterministically narrow by same-row selected size/color, then ask only the remaining lace condition with width-scoped title/page evidence. Keep pet-fence compound counts, the three shelf types, the blanket-set condition, and the remaining two multi-option product cases to test compound/unknown behavior. Generate no synthetic benchmark cases.

Before inference, verify all 14 case IDs, full AU row counts, raw source refs, model-input byte/token budgets, and that every residual requirement appears in a task. Smoke-test the output schema locally with no model call: one relation, integer evidence slots only, invalid output => review. Freeze task JSONL/config/code/source hashes. Run only after that freeze, save raw JSONL and schema/parser failures first, and compare row-key decisions to the unchanged v10 constrained-pair baseline. Do not accept a claim of model gain from case-level matches alone: verify exact accepted AU row keys, false accepts, model-added correct row accepts, review/coverage, and curtain/non-curtain breakdown. Open labels only after all raw outputs and hashes are durable; this reused 14-case set cannot establish generalization.

Keep v10 CPU source gate unchanged

The established constrained-pair CPU gate currently has 337 source-supported matches in the 1,383-case pool, while the residual GLiNER run produced no model-added correct accepts. The audited count-conservation residual ablation retained 296/337 matches and reduced non-curtain recall substantially. Therefore keep the 337-match CPU gate as the current baseline. Treat the residual model as a proposal only; adopt it only if a new frozen task demonstrates additional correct row-key accepts while retaining the current source-supported results and producing no false accepts on the audited set.

No existing raw, labels, evaluator, GPU run, or source file was modified. The only new artifact in this task is this design memo.
