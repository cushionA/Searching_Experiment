Portable pre-AI routing fixtures

fixtures.json has nine source-backed examples and four clearly synthetic boundaries. Expected values are routing assertions only, not gold product-pair labels or accuracy claims. Rules are ordered JAN, merchant code, exact full manufacturer model, normalized full-title equality, then AI. Assumes same seller and product-level matching; does not require capacity/quantity/set consistency, does not auto-match from images, and uses AI for unresolved cases.

For each actual evidence record, source.appdata_file and appdata_sha256 identify the native captured page JSON from the acquisition manifest. source.product_file and product_sha256 identify the compact product JSON file from that same manifest; the SHA-256 is over its exact file bytes. source.product_root_in_appdata is the JSON path where that exact product object appears inside the native page JSON. Each evidence field path is relative to that product object. comparison_mode is machine-checkable: equals requires exact JSON value equality; contains requires the string excerpt to occur in the source string. All actual excerpts and root mappings were verified against both product JSON and the indicated native appdata JSON. Synthetic cases have no source files or hashes.

Route IDs are canonical: JAN / MERCHANT_CODE / MODEL / TITLE / AI. Each field path is relative to the product object. Actual fixtures are excerpts; use comparison_mode for source validation, not a claim that each excerpt equals the whole field. Synthetic fixtures use the same product-relative field-path notation.
