# サイトマップURL群を軽量エージェントへ渡す経路生成の実測

## 結論

Scraping Sandboxで、サイトマップのURL群→Lunaが一覧候補を選択→実行器が一覧を開く→スクロール→初期表示外の商品3件のraw HTMLと描画DOMを保存、まで実行できた。保存した規則を会話履歴のない別プロセスへ読み込み、別一覧から未観測の商品3件も新規取得した。巡回実行器のLLM・埋め込み・ローカルモデル推論は0。

ただし実行可能性の小試験である。9サイトを事前に選定し、一連のスクロール取得を確認できたのは1/9サイト。サイトマップURLを得られた7サイトでは1/7、一覧DOMを得られた6サイトでは1/6。全80サイトへ外挿しない。このpilotだけを全80サイトの運用分母に置くと確認1・残り79は未確認であり、うち71サイトは未実施。過去のB1/C1/B2結果を上書き・合算していない。

商品詳細の型は、自動判定と独立した後評価を区別する。凍結した自動判定器はweb-scraping.devの6件だけを確認した。簡素なデモ商品のHTMLにはschema Productや購入操作がなく、自動判定だけではScraping Sandboxを確定できなかった。別のLuna評価ジョブへ保存本文の短い要約だけを渡し、Listly3件・Scraping Sandbox初回3件と再実行3件を詳細型と確認した。これは固定URL正解集合による到達率ではなく、後評価による確認である。自動判定のscore.jsonは変更していない。

採用候補は「URL群を圧縮して初回だけ軽量LLMへ渡す＋DOM反復リンク規則＋スクロール実行器」。既存Skillへ標準採用するには、目的型の汎用検証と探索候補の選び直しを改善する必要がある。

## 入力と候補選択

対象は既存80サイト内の02/03/05/06/07/09/10/14/36。9サイトは今回のサイトマップ取得結果や候補出力より先に選んだ。14/36は過去の保存inventoryを移転し、今回の新規metadata通信0、元費用は移転元runへ参照した。実サイト2件は対照で、全サイトにスクロールがあると仮定していない。

練習7サイトへrobots/sitemapの新規取得を行い、5サイトでURLを得た。ID03とID07では今回URLを得られなかった。全9サイトのURL記録は8,213件。URLの数値・末尾slug・query key・末尾slashを型へまとめ、代表URL、件数、親prefix候補、ユーザー指定入口の対象範囲をLunaへ渡した。query/hash付き実URLは保持した。親prefixはリンクの存在を証明しない仮説として明示した。

元のURL列は762,609文字、成功した選択ジョブのサイト別JSON payload合計は76,215文字。約1/10への文字数圧縮であり、トークン削減率・料金削減率ではない。省略されたグループも記録した。特にNASAなど大規模サイトのURL一覧は部分的である。

候補の選択はrequested model gpt-6-luna、fork履歴なし。提供JSON以外のページ本文、正解経路、評価ポリシーを読ませていない。ID・URLは提示候補内に限定してプログラムで検証。モデルの実IDはprovider側から独立検証できていない。

初回の一括payload受け渡しはツール出力が途中で切れ、存在しないrequest ID等が混ざった。取得には使わず入力・回答を保存。入口の目的範囲と浅いliteral URLの保持も補い、各サイトを別々に完全読込する1回の修復後、7回答を検証できた。選択2ジョブを実施し、内部モデル呼出数・入力出力トークンはunknown。初回失敗の費用を0扱いしない。

7サイトで一覧・ハブ候補、2サイトで詳細URL型を選べた。残る5サイトでは詳細URL型が不明であり、実行器が一覧の非navigation領域にある反復リンク群からURL型を学ぶ汎用fallbackを使った。LLMがURLだけから全グラフを作った成果とは扱わない。

## 実行方法

入口はpython -B -m jse.lab structure-routing。既存grounding runのstate.jsonがある場所では実行を拒否し、元のgrounding予算をリセット・迂回しない。今回の経路ベンチマークは独立したprotocol・robots・metadata上限・document guard・操作上限・台帳・証拠を使う。既存adaptive transportがスクロールに対応したと主張するものではない。

Chrome157/Playwright1.63、fresh context/Cookie、cache無効、service worker無効、ja-JP/Asia-Tokyo、1365×900。サイト内同時実行1、metadataは最大4サイト。練習はページ間1秒以上、実サイトは5秒以上。初回探索は最大6候補、詳細は最大3件、スクロールは最大6操作。途中のリンク、DOM、状態ID、raw/描画HTMLを保存した。

エージェントの候補順は保存し、実行器はscroll/infiniteを含む候補を優先する汎用規則を使った。実際に観測したリンクをたどり、詳細へは一覧に存在したリンクだけから進む。サイト専用selector、固定商品ID、手書きの正解経路の追加は0。derived prefixへの最初の到達は仮説URLの確認であり、実在リンクとして捏造しない。

robots拒否・403/429・ログイン等では停止した。Web ScraperとMagicScraperは一覧・スクロール後リンクを得たが、詳細パスのrobots拒否を確認して終了した。後続のwarmは実行していない。N/Aはサイト全体に機能が存在しないという意味では使わず、選択した一覧で追加表示が観測できなかった場合はそのまま記録した。

## 到達の証拠とG/R

Scraping Sandboxのサイトマップは入口・デモの5 URLだけで、取得した商品詳細URLは載っていない。Lunaが選んだ/infinite-scrollを開き、スクロール後のDOMで/product/21、22、23を実観測して、新規4文書（一覧1＋詳細3）をロードした。実行器が学習した/product/:number型で選択し、raw/DOMを保存。スクロール前後のHTMLからも、3リンクが初期表示外だったことを独立に照合した。型は独立後評価、引用証拠は提供要約と一致した。

同一URLの再実行はweb-scraping.dev。同じ/products一覧と同じ詳細URL3件を、別プロセス・新しいブラウザcontextで再取得して3/3確認。保存HTMLを読んだだけの件数は0。ただし既観測グラフ内の経路検索を独立に採点した試験ではなく、Gの厳密な成功数・分母は0/0で未実施とする。保存recipeと反復リンク規則の再実行と、グラフ経路検索を混同しない。

Rの小試験はScraping Sandbox。保存recipeを別プロセスで読み、初回に本文を取得していない/data-table一覧へ適用。初回の21〜23とは異なる/product/1、2、3のraw/DOMを新規取得し、独立後評価で3/3を詳細型と確認した。warmのスクロール追加は0で、別一覧への規則転用と初回の無限スクロール成功を混同しない。warm取得中のモデル呼出0。

これらは各3例の到達・再利用確認で、候補に依存しない固定URL集合へのrecallや網羅率ではない。固定URL recall、80サイトベンチマークの点数はnull。共通の自動型判定がまだ不足しており、Rの成功率を一般化できる実験規模でもない。

## 独立評価の限界

期待型・URL範囲のポリシーを候補出力前に評価環境へ凍結し、候補に渡さなかった。自動判定器は、保存raw/DOM、hash、本文、ブロック/ログイン/空SPA、Product構造化データ等を検査した。score.jsonの固定ポリシー確認は20候補中6件、未確認14件。自動判定でスクロール後の詳細型まで確定した数は0。

一方、Listlyの/goods/は評価URLパターン外、Scraping Sandboxの商品詳細はschema Product/購入操作がなく、保存したHTMLだけで自動成功としなかった。後評価のLuna2ジョブへ6件＋3件の短い本文要約と見出し等を渡し、9件を詳細と判定。これは実行器へフィードバックしておらず、取得や規則生成の判断には使用していない。型確認の自動化が完了したとも扱わない。

自動確認6＋後評価確認9＝15件、用途違いのNASA3件、取得拒否2件で20候補を保持した。raw/DOMを保存できた数18と、目的型確認15を分ける。後評価はAIによる要約確認であり、人間による全文監査ではない。

さらに、確認済み詳細DOMの厳密な構造hashをwarmへ当てる実験は3件とも不一致だった。これで自動的に型確認できたとはしない。template-validation.jsonに失敗を保存し、成功に合わせて正規化や閾値を変更していない。

## 費用・失敗・モデル使用

完了したブラウザ処理はdocument予約37、UI操作84、HTTP1,101、XHR/fetch98、browser処理時間173.994秒。別途robots9要求、今回のサイトマップ/robots metadata38要求・447,205 bytes。記録できた新規HTTPは計1,148要求。decoded body bytesは完了応答のみでwire通信量ではない。

Web Scraperの最初の試行では、詳細遷移後の観測が長引き、6スクロール状態を保存した段階で停止した。厳密なHTTP・XHR・UI・ブラウザ時間はunknown。文書は上限9を予約として別計上し、完了分37と合わせ最大46。UIは失敗試行の上限15を別記する。HTTP1,148や173.994秒を中断分込みの全費用と呼ばない。

実行器のevaluate/content/raw bodyに期限がなく、拒否後の画面観測でも待つ不備を修復した。DOM読取15秒、raw body5秒、遷移45秒、phase600秒の上限、進捗・文書予約の途中保存、finallyによる部分結果保存を追加。元の途中保存物はaborted-001へ保持。以後の実行source hashはexecution-source-bounded.jsonと一致した。

選択用Native Lunaは初回失敗＋修復の2ジョブ。評価用Native Lunaは2ジョブ、提供要約の合計16,702文字。内部モデル推論回数・入力出力トークン・設計/コード/報告のNative使用量はunknown。ジョブ数をモデル推論回数に置き換えず、unknownを0と報告しない。従量LLM/外部embedding API呼出0、実行器のページ巡回LLM/embedding/localモデル推論0。新しい有料クラウド環境は作っていない。

100件連続処理は今回未実施。件数を増やしてもLLM0で回る保存recipeの再利用は確認したが、大量処理時の取得費用・失敗率の推定はしていない。

## Skillへの統合案

最小構成は、robots/sitemap→URL型と浅い入口の圧縮→初回Lunaの候補選択→観測リンクの確認→反復リンク規則とスクロール条件の保存→モデルなし巡回。保存JSONをそのまま実行器へ渡す。MiniLM/Qwen等の新しい重みは今回不要だった。

追加で必要なのは、目的型と一覧型を区別する汎用検証、URL群が目的範囲を代表しない場合の扱い、候補一覧の選び直し、反復リンク群が検索リンクやnavigationを拾う失敗への対応。今回Load Moreクリック、Shadow DOM、iframe操作、仮想scroll全体の保証はしていない。スクロール途中DOMは保存したが、全形式の状態復元は未検証。

ソースコードとfixturesは新規6ファイル、ラボ入口はjse/lab/__main__.pyに追加。型判定の自動化や、全80サイトへの展開まで完了した成果としてSkillへ組み込まない。

## 再開・保存

HANDOFF.mdとSTATUS.json、summary.json、route-verification.jsonを入口にする。完了済みphaseは再取得せず、phase結果からresults.jsonlの欠落も復元する。中断時は進捗と文書予約を保持し、残予算に計上する。根拠なく新runへ切り替えて予算をリセットしない。

NodeのURL圧縮/候補制限/中断再開6件、browserの期限読取とlocalhost cold/warmを含む7件、独立HTML検証8件、ラボCLI5件は通過。プロジェクト指定test_labは86件中2失敗・5skip。CamoufoxのWindowsパスとproxy NO_PROXYの失敗は前回と同じ内容で、今回修正していない。ログを保存した。
